# ADR-0001 实验证据：PNG编码升级的等像素、微变化与旧引用读取

本文件记录 docs/adr-0001-png-encoding-identity.md 的全部量化依据。环境：go1.24.10 linux/arm64（Linux aarch64，OrbStack虚拟机），Python 3 标准库。复现：`python3 scripts/encoding-lab/run.py`（默认在临时目录构建与运行，不修改仓库源码与任何既有数据根）。

## 方法

- **binA（现状）**：仓库源码原样构建，PNG为stdlib默认压缩。
- **binB（升级后）**：用 `go build -overlay` 在构建期替换 internal/raster/raster.go 的编码调用为 `png.Encoder{CompressionLevel: png.BestCompression}`，仓库文件不改动；模拟"只换压缩器、像素管线不动"。
- **pngtool**：仅用stdlib的解码/重编码/像素比较工具（scripts/encoding-lab/pngtool.go），与服务同源编解码。
- 全部行为经真实HTTP驱动（与 scripts/walkthrough.py 同法），数据根在临时目录；方案A行为为实测，方案C/D为基于实测字节的模型推演（本交付不实现）。

## 阶段1：升级前基线（binA）

对 examples/amber-proof.json 建版并追加两个真实修订（rev2：镂空内边124→123，1px真实变化；rev3：青色层透明度0.82→0.80），逐稿本渲染：

| 稿本 | 字节 | 渲染耗时样本(ms) | 身份键公式复核 |
|---|---|---|---|
| rev1 | 4436 | 47.63 / 47.27 / 48.00 | 一致 |
| rev2 | 4427 | 44.33 / 47.32 / 43.82 | 一致 |
| rev3 | 4430 | 45.07 / 46.79 / 46.60 | 一致 |

- 身份键 `sha256(plate:revision:scene_digest:format:bytes_digest)` 与服务返回id 3/3一致。
- 重复渲染无加速（每个稿本第2、3次为同键重复渲染，耗时无下降）：现行提交路径先栅格化后查键。
- rev1成品开校样并accepted；DELETE该成品→409；If-None-Match→304。
- 快照24,391字节/3成品；重启后GET rev1字节与ETag完全一致（恢复路径基线成立）。

## 阶段2：同数据根升级到binB

| 检查 | 结果 |
|---|---|
| 旧成品GET字节一致 | 3/3一致 |
| ETag与升级前一致 / 304 | 3/3一致 / 有效 |
| accepted校样钉住的成品DELETE | 409（保持） |
| 重渲染产生新id/新摘要 | 3/3全部变化（3470/3469/3492字节，均值−21.53%） |
| 重渲染与原件像素差 | 3/3精确RGBA差0（等像素异编码成立） |
| 快照/对象 | 24,391→39,440字节（+61.7%）；3→6对象 |
| 现有确定性断言（walkthrough png/artifact/restore/bundle的"重渲染摘要不变"） | 3/3将失败 |

结论：方案A的旧引用保护零成本成立，但等像素重渲染的存储与对象放大是实测事实；现有验证契约把字节确定性当不变量，升级必须有去重配合。

## 阶段3：局部真实变化（64×64实验版，binA）

底稿D0：左半幅α=0.004（量化后A=1）隐藏红色，右半幅不透明卡片含8×16镂空。逐修订单变量改动后渲染比较：

| 对比 | 精确RGBA差异像素 | 单通道最大差 | 视觉差异(容差0) | 视觉差异(容差2) | 像素哈希 | 稿本摘要 |
|---|---|---|---|---|---|---|
| D0↔D1 隐藏颜色红→蓝（α不变） | 2048 | 255 | 2048 | **0（被吞）** | 不同 | 不同 |
| D0↔D2 镂空边移动1px | 16 | 255 | 16 | 16 | 不同 | 不同 |
| D3↔D4 α=0隐藏红↔蓝 | 0 | 0 | 0 | 0 | 相同 | 不同 |
| D0↔D5 顶点移动0.01px | 0 | 0 | 0 | 0 | 相同 | 不同 |

结论：
- 精确RGBA键区分所有渲染器可观测变化（含1px镂空、低透明隐藏颜色）；带容差的"视觉"键会把2048像素、Δ255的真实差别吞掉——方案B风险的量化。
- 折叠安全边界=渲染器自身可观测性：α=0像素在量化前已被 paint.RGBA8 归一化为(0,0,0,0)，亚采样移动不触达4点覆盖采样；这些差别在任何编码器输出中都不可观测，折叠不损失消费者事实。
- 所有对比的稿本摘要均不同：身份事实（谱系）与像素事实是两类事实，前者永不折叠。

## 阶段4：离线重渲染（封包导出→新数据根导入，binB）

| 检查 | 结果 |
|---|---|
| 导入后重渲染rev1的id/摘要与源成品 | 不同（3470字节，新编码器） |
| 与源成品像素比较 | 精确一致 |

结论：封包本就不含成品；跨系统等价性只能由像素哈希证明，身份不可移植是既有设计而非升级引入。

## 阶段5：转码等价与计算复用

对阶段1保留的原件字节"解码→按BestCompression重编码"，与binB原生重渲染字节对比：

| 稿本 | 原件字节 | 转码字节 | 与binB原生渲染字节一致 | 解码 | 解码+编码 |
|---|---|---|---|---|---|
| rev1 | 4436 | 3470 | 是 | 1.00ms | 21.4ms |
| rev2 | 4427 | 3469 | 是 | 1.01ms | 21.1ms |
| rev3 | 4430 | 3492 | 是 | 1.00ms | 20.3ms |
| 512×512场景 | 8530 | 5878 | 是 | 8.44ms | 37.6ms |

- 512×512渲染耗时：binA约377ms、binB约406ms（含HTTP）；转码37.6ms且不占2个计算名额——约10倍节省。
- 方案C的启动索引代价：解码约1.0ms/成品（192×144）至8.4ms/成品（512×512），256对象上限内一次性约0.26～2.2s，可惰性构建。

## 存储与容量模型（基于实测字节，快照内联base64 ×4/3）

单个稿本"升级前渲染+升级后重渲染"的代价：

| 方案 | 新对象 | 新快照字节 | 旧引用 |
|---|---|---|---|
| A 每编码各持原件 | 2 | (4431+3477)×4/3 ≈ 10.5KiB | 全部保持 |
| C 提交时精确像素去重 | 0 | 0 | 全部保持 |
| D blob分层（变体惰性） | 1（元数据行） | ≈1KiB元数据；变体被索取时才+3477×4/3 | 全部保持 |
| B 视觉折叠丢旧字节 | 0 | −（净减） | **100%悬空** |

容量投影：256对象上限（含已撤销，单调）下，A与"D全量物化变体"在128次重渲染后耗尽；C对等像素场景零增长。128MiB字节上限在本规模下不是先决约束；真实压力是每次提交全量重写快照（实测3次重渲染即+15KB）。

## 复现

```sh
python3 scripts/encoding-lab/run.py            # 全部阶段，输出facts.json与PNG样本到临时目录
python3 scripts/encoding-lab/run.py --keep /tmp/encoding-lab   # 保留运行目录便于检查
```

原始输出：facts.json含全部id、摘要、字节数、耗时与逐对像素差；本文件表格即其摘录。
